# HalfTrend research: discrepancy corrections

This repository analyzes supplied NIFTY index observations using the existing
HalfTrend logic. This stage corrects data handling, statistics, OOS consistency,
and accounting only. No futures/options strategy, parameter optimization, or
market-data download is introduced.

See [the discrepancy-resolution report](DISCREPANCY_RESOLUTION.md) for corrections,
intentional behavior changes, exclusions, assumptions, and verification evidence.
Existing files under `results/` remain historical artifacts with the audited
limitations; they have **not** been regenerated by this correction stage.

## Data policies

```python
from src.data import load_minute_data, resample_to_15m

minute = load_minute_data(csv_path)  # rejects conflicting duplicates, exports audit
# An intentional exclusion, if selected:
minute = load_minute_data(csv_path, duplicate_policy="exclude", audit_dir=audit_dir)
bars = resample_to_15m(minute, minute_label="start", audit_dir=audit_dir)
```

CSV timestamps are explicitly parsed as `%d-%m-%Y %H:%M`, localized to
Asia/Kolkata. Duplicate policies are `reject` (default), `exclude` (entire conflicting
group), `first`, and `last` (stable CSV order). Duplicate source rows and decisions
are exported, and any non-reject resolution emits a warning. Exact duplicates
are collapsed with a recorded decision and warning, rather than silently counted
twice. No input CSV is rewritten.

`minute_label` must explicitly be `"start"` or `"end"`. End labels shift backward
one minute before aggregation. Dataset coverage supports start labels (375 minutes
from 09:15 to 15:29), but the Kaggle dataset's producer convention is unverified;
no vendor metadata or dataset URL was supplied. Start labels are an explicit
verification assumption, not automatic inference or proof of producer semantics.

Bars are anchored to 09:15 local time, left-closed/right-open. A normal
09:15-15:30 session has **25 complete 15-minute bars**. The index labels bar starts;
`bar_open` is the first observed interval start and `bar_end` is the final observed
minute's interval end. Signals are available at bar_end, and fills occur at the
next observed bar_open. Partial bars never invent an earlier fill or later mark.

Defaults include regular-clock observations (09:15 <= start < 15:30) and exclude
incomplete bars. `partial_bar_policy="include"` explicitly retains observed partial
bars. Evening observations (17:00 <= start < 21:00) are classified separately and
excluded unless `include_evening=True`; other out-of-session observations stay
excluded. Classification uses local clock times, not an inferred exchange calendar.
Weekend/special sessions and missing sessions need external calendar verification.
Complete regular bars on an otherwise incomplete day are retained. No synthetic
candles, holiday fills, or missing-price forward filling are introduced.

All-zero volume is converted to NaN and marked unavailable. It does not imply
no trading and does not filter observations.

## Performance conventions

Starting capital is timestamped at the first evaluated observed open; terminal
equity is timestamped at the last observed interval end. These timestamps are
explicit on PortfolioResult and HalfTrendBacktest and in saved convention metadata.
CAGR uses `(terminal_equity / initial_capital) ** (1 / elapsed_years) - 1`, where
elapsed_years is elapsed seconds / (365.25 * 86400). Changing intermediate bar
count alone cannot change CAGR.

Sharpe and Sortino use daily marked-to-market equity returns, annualized at
252 observed trading sessions/year. The last included mark of each local session
date is used; weekends and missing sessions are not added as zero-return rows.
The first daily return includes changes from initial capital. Annual risk-free
rates default to zero and are divided arithmetically by 252 for daily excess
returns. Sharpe uses sample standard deviation (ddof=1). Sortino preserves the
QuantTools convention: sample standard deviation of negative excess observations,
not RMS shortfall over all observations. Fewer than two downside observations or
constant downside values produce an undefined Sortino ratio.

Calmar uses that same calendar CAGR / abs(maximum drawdown). Drawdowns include
starting capital as the initial peak. Drawdown duration remains a count of strictly
underwater evaluated bars, including open drawdowns; it is not a completed recovery
time or a calendar duration. Undefined ratios are NaN in Python summaries and
null in JSON, with reasons in `undefined_metrics`. Insolvency/invalid inputs raise
rather than being reported as an undefined metric or replaced with zero returns.

## Sizing, fees, and OOS boundaries

Gross research deploys available cash with fractional index-equivalent quantity.
The existing costed sizing rule is retained explicitly:
`q = cash * (1 - cost_bps / 10000) / entry_price`. Quantity is fixed within each
trade. This is a research notional model, not futures lot sizing or a claim that
spot index units can be executed.

Fees are `quantity * actual_fill_price * fee_rate` separately at entry and exit;
fills use the next observed open with no simulated slippage. Fees and slippage are
separate concepts; no spread/slippage estimate is embedded in cost_bps. The
cash-and-position model retains residual cash of approximately `cash * rate**2`
that the old multiplicative curve erased. It does not silently switch to
`cash / (entry_price * (1 + rate))` sizing. Actual-quantity ledgers and equity now
come from this same model, with independent reconciliation.

5 bps **per side on underlying notional** is the primary verification baseline.
0, 8, and 10 bps are gross/stress diagnostics. **2 and 3 bps on option premium are
reserved for a later options stage**, not applied to index prices here. Nonfinite
or negative costs are rejected. There is no arbitrary cost cap. The retained
entry sizing formula mathematically requires `1-rate > 0` for positive quantity;
an attempted entry violating that condition raises. Standalone fee arithmetic
on an already explicit quantity has no arbitrary sizing cap. Starting capital,
prices, and quantities must be finite and positive; nonpositive/nonfinite portfolio
equity raises an explicit InsolvencyError.

Closed `net_pnl` already includes both fees. Final equity is reconciled independently
as `initial capital + closed net P&L + open gross P&L - open entry fee`. A second
identity reconstructs cash and positions from recorded fills. Open positions are
marked at the last close without forced liquidation or a fictitious exit fee.
`gross_pnl` and `net_pnl` in the unified ledger are actual cash P&L; `pnl_points`
retains per-unit price changes. The legacy generate_long_only_trades wrapper still
returns point P&Ls, while current research runners use the cash ledger.

The full-history causal HalfTrend calculation is sliced into the fixed existing
IS/OOS windows and reused by every cost scenario. Each evaluation starts with the
same capital, flat positions, and no imported pre-boundary pending signal. There
is no automatic forced exit at the end. The zero-cost scenario must reproduce
the main gross OOS ledger, fills, and equity exactly.

## Verification only

From the repository root:

```bash
python -m pytest
python -m ruff check .
python -m black --check .
python -m tests.check_cost_reconciliation
python -m tests.verify_discrepancies
```

Verification requires pandas, NumPy, the local quant-research-tools library,
pytest, Ruff, and Black. No dependency installation or network data retrieval was
performed in this stage. The bounded verification script records the actual data
hash and policies, audits the full input CSV, and simulates **only the first 1000
retained bars** at 5 bps. It does not regenerate full research results. Output is
under `verification/discrepancy_fix/`, separately from `results/`. Original result
hashes and backups of the pre-existing user-edited cost files are retained there.

Full research runners are deliberately not run during this stage. Their APIs
require an explicit minute-label convention; duplicate rejection remains the
default. Output writing is opt-in and refuses to overwrite existing files.
